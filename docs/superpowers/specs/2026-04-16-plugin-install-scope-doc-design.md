# 插件安装作用域文档修订设计

## 背景

当前仓库的 README 和 release notes 模板虽然已经要求使用带明确版本号的安装/升级命令，但没有把 **安装作用域** 写清楚。

现场问题已经证明这会直接误导用户：

1. 用户按 README / Release 正文里的版本化命令执行升级。
2. 命令里没有 `-g/--global`。
3. upstream `plugin install` 逻辑会把这次安装写到当前项目目录下的 `.opencode`，而不是全局 `C:\Users\34404\.config\opencode\opencode.jsonc`。
4. 真正接管 live broker 的实例链如果走的是全局配置，就仍会继续使用旧缓存版本。

因此，这次文档问题不是“没写版本号”，而是“没有把全局安装和项目局部安装的语义区别写清楚”。

## 目标

1. 把默认用户路径明确成“更新你平时实际在用的 OpenCode 实例”，也就是带 `-g/--global` 的全局安装/升级。
2. 保留项目局部安装这条能力，但明确它是高级/局部路径，不是默认升级方式。
3. 让 README 和未来 release notes 模板的口径一致，避免再次误导用户只更新当前仓库 `.opencode`。

## 非目标

1. 不改 OpenCode 自身的插件安装机制。
2. 不重写历史远端 GitHub Release 正文。
3. 不讨论 bare 包名缓存策略以外的更大安装流程重构。

## 方案选择

### 方案 A：默认区分全局/局部路径

做法：

1. README 默认示例命令统一改成带 `-g` 的全局安装/升级。
2. README 额外说明：不带 `-g` 只会改当前项目目录下的 `.opencode`。
3. `docs/release-notes-template.md` 的 `## 升级方式` 示例命令也改成带 `-g` 的全局命令，并补一句局部安装说明。

优点：

- 直接修复这次真实误导点。
- 对大多数用户最贴近实际使用场景。
- 不会把“局部安装”能力误删掉。

缺点：

- 文档会比之前多一层作用域说明。

### 方案 B：全部一刀切为全局安装

做法：

- 所有文档只保留 `-g` 路径，不再提局部安装。

优点：

- 最简单。

缺点：

- 会把项目局部安装这条真实能力从文档里抹掉。
- 对需要仓库内单独绑定插件版本的场景不友好。

### 方案 C：只在 README 解释作用域，模板保持不动

做法：

- 只改 README，中英补充 `-g` 语义。

优点：

- 改动最小。

缺点：

- 后续 release 正文仍可能继续沿旧模板生成无 `-g` 的误导命令。

### 结论

采用方案 A：默认区分全局/局部路径，同时把 README 和 release 模板一起修正。

## 设计细节

### 1. README 默认命令

README 中英文安装/升级说明的默认示例命令改成：

```bash
opencode plugin opencode-copilot-account-switcher@x.y.z --force -g
```

表达的语义是：

- 默认要更新的是你平时实际启动的 OpenCode 实例链。
- 这条链在大多数机器上会读全局 `C:\Users\...\.config\opencode\opencode.jsonc`。

### 2. README 对局部安装的说明

README 必须额外写清：

- 如果去掉 `-g/--global`，这次安装只会改当前项目目录下的 `.opencode`。
- 这适合“只想让当前仓库绑定一个特定版本插件”的高级场景。
- 它不是默认升级路径，也不能保证你平时启动的其它 OpenCode 实例会一起切版本。

### 3. Release 模板的默认升级方式

`docs/release-notes-template.md` 中 `## 升级方式` 的示例命令也必须改成带 `-g` 的默认全局命令。

同时补一条说明：

- 如果某次 release 明确针对项目局部安装场景，正文必须额外解释不带 `-g` 的作用域，而不是让读者自己猜。

## 验证边界

本轮只验证以下 4 件事：

1. README 中文安装/升级说明默认示例命令改成带 `-g` 的全局命令。
2. README 英文安装/升级说明默认示例命令也改成带 `-g` 的全局命令。
3. README 明确写出“不带 `-g` 只会改当前项目 `.opencode`”。
4. `docs/release-notes-template.md` 的 `## 升级方式` 示例命令改成带 `-g`，并补一条局部安装作用域说明。

## 成功判定

当这次文档修订完成后，应满足：

1. 用户不再会因为照抄版本化命令却忘记 `-g`，只更新当前仓库 `.opencode` 而误以为自己已经全局升级。
2. README 和未来 release notes 模板对安装作用域的表达一致。
3. 项目局部安装仍被保留，但明确被标注为非默认路径。
